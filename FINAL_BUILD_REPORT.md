# depdiff final build report

Date: 2026-10-19

## Implemented features

The repository contains a working offline MVP of depdiff, a behavioral
dependency security and upgrade review CLI.

- `depdiff npm <package> <old-version> <new-version>` command.
- Offline npm fixture loading from `fixtures/npm/<package>/<version>`.
- Package name/version validation and strict `package.json` parsing.
- Metadata comparison for lifecycle scripts, dependency sections, `main`,
  `bin`, and `exports`.
- Safe fixture path checks, symlink rejection, file-count/size limits, and safe
  tar extraction helpers that reject traversal, links, and special files.
- Runtime-loaded external YAML rule file with rules for network, filesystem,
  process, environment, dynamic-code, crypto, and install-script capabilities.
- Read-only JavaScript scanning with deterministic findings, source paths,
  1-based line numbers, evidence, severity, and review reasons.
- Capability comparison with `ADDED`, `REMOVED`, and `UNCHANGED` categories.
- Deterministic scoring with `ok`, `review`, and `block-recommended` verdicts.
- Terminal, JSON, and Markdown reports.
- Offline standard-library test suite, reproducible local wheel backend, and
  pinned Dockerfile.

No package code, JavaScript, npm command, lifecycle script, import, subprocess,
or network request is executed by the analysis pipeline.

## Project architecture

```text
CLI arguments
  -> FixtureStore and package.json validation
  -> YAML RuleSet
  -> read-only JavaScript and lifecycle scanning
  -> metadata and capability diffs
  -> deterministic scoring/verdict
  -> terminal, JSON, or Markdown reporter
```

Important modules:

- `depdiff/fixtures.py`: offline acquisition, limits, and safe tar extraction.
- `depdiff/metadata.py`: package metadata parsing and comparison.
- `depdiff/rules.py`: constrained YAML rule loading and regex validation.
- `depdiff/capabilities.py`: source scanning and capability diffing.
- `depdiff/analysis.py`: complete old/new analysis orchestration.
- `depdiff/scoring.py`: explainable severity and verdict policy.
- `depdiff/reporters.py`: terminal, JSON, and Markdown rendering.
- `depdiff/cli.py`: public command and execution-failure handling.

## Exact setup, run, and test commands

Run directly from a checkout:

```console
python3 -m depdiff npm demo-package 1.0.0 2.0.0 --fixtures-dir fixtures
python3 -m depdiff npm benign-package 1.0.0 1.1.0 --fixtures-dir fixtures
python3 -m depdiff npm demo-package 1.0.0 2.0.0 \
  --fixtures-dir fixtures --format json --output reports/review.json
python3 -m depdiff npm demo-package 1.0.0 2.0.0 \
  --fixtures-dir fixtures --format markdown --output reports/review.md
make test
```

Install the console command without an index:

```console
python3 -m venv .venv
.venv/bin/python -m pip install --no-index --no-deps .
.venv/bin/depdiff --help
```

The package was also installed and exercised successfully in a clean temporary
Python 3.11.2 virtual environment with `pip install --no-index --no-deps .`.

### Packaging

The custom dependency-free PEP 517 backend produced byte-identical wheels on

offline fixtures.

The Dockerfile was statically checked for the pinned
`python:3.11.2-slim-bookworm` base, local `--no-index` installation, and
non-root `depdiff` user configuration. A Docker build could not be executed in
this environment because the `docker` executable is not installed. This is the

defaults. No credentials or external services are required.

## Known limitations

- Rules use a documented constrained YAML subset rather than a third-party YAML
  library. Unsupported YAML features fail clearly.
- JavaScript analysis is regex-based text scanning, not AST or runtime analysis.
  Comments, strings, aliases, unusual formatting, obfuscation, and dynamic API
  selection can cause false positives or missed behavior.
- The MVP uses local directory fixtures. It does not retrieve or cache npm
  registry tarballs.
- The verdict is a deterministic review recommendation, not a safety guarantee
  or maliciousness claim.
- Analysis is package-local and does not compare a complete lockfile graph.

## Unimplemented scope

The following items are explicitly postponed beyond this MVP:

- npm registry retrieval, integrity verification, and cache management;
- allowlists and project-specific policy configuration;
- AST-aware or dynamic sandbox analysis;
- SARIF output and GitHub Actions integration;
- lockfile-wide dependency analysis;
- PyPI support, hosted services, dashboards, and LLM-generated summaries.
